## Контракт v2

`src/gigachat.mjs`: OAuth Basic `GIGACHAT_API_PERS`, UUID RqUID, access token в памяти с обновлением за минуту до истечения; один повтор после 401. Авторизация — `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`, генерация — `https://api.giga.chat/v2/chat/completions`.

Передаются девять отдельных схем функций BOB в `tools.functions.specifications`, без `reply_user` и встроенных инструментов. `model_options.parallel_tool_calls=true` поддерживается Ultra; `max_tokens=900`, общий timeout хода ограничен. Ответ `messages[].content[].function_call` преобразуется в один пакет до пяти вызовов. Дальше работают существующие `decodeCalls`, схемы и `Assistant.prepare`: исходная дата/длительность разбираются кодом, проверяются права, выбор дела, конфликты и неизменность внешнего срока. Произвольный текст не исполняется. Неизвестные функции/поля и некорректные пакеты блокируются.

Локальные команды, простые действия и фильтр непрофильных запросов предшествуют любому LLM. Cloudflare остаётся по умолчанию. Выбор провайдера требует отдельного личного согласия в `/providers`; автоматического перехода на другой/платный источник нет. Объём передаваемого контекста описан в форме согласия, не включаются ключи календарей или аудиозапись.

## Защищённый транспорт

Реальный Worker получил HTTP **526** на обоих GigaChat-адресах без отправки ключей или данных. [Документация GigaChat](https://developers.sber.ru/docs/ru/gigachat/certificates) требует CA Минцифры; [Workers node:https](https://developers.cloudflare.com/workers/runtime-apis/nodejs/https/) не поддерживает пользовательский `ca`.

Проверено локально: официальный PEM скачан с `https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt` по обычному HTTPS с проверкой сертификата. SHA-256: `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`, действителен до 27 февраля 2032. Node получил проверенное TLS-соединение: models 401 и OAuth 400 без авторизации, затем разрешённые OAuth/модели/синтетические генерации с ключом.

`src/gigachat-node.mjs` ограничивает CA конкретными фиксированными GigaChat URL/методами, запрещает перенаправления и произвольные адреса, сохраняет `rejectUnauthorized=true`, ограничивает тело/ответ и время. Windows, `globalAgent` и остальные провайдеры не меняются. Это исходящий транспорт; сам мост теперь подготовлен и проверен, но ещё не развёрнут (`gigachat-bridge.md`). Исследование размещения — [free-gigachat-hosting.md](free-gigachat-hosting.md), bob-wrh.26.

## Квоты и границы включения

`ProviderLedger` считает отдельные tokens, не neurons: общий локальный предел 500 000 в UTC-день, личный 20 000 и 100 запросов, пожизненный предел выбранного пакета `GIGACHAT_TOKEN_CAP`. Для Ultra он не должен превышать фактический остаток **50 млн**, не 250 млн Lite. Один незавершённый GigaChat-запрос во всём BOB. Резерв до сети: UTF-8 bytes + output limit + запас; списание — `usage.total_tokens`, неизвестный результат списывает резерв. Баланс пакета не восстанавливается каждую полночь. Это учёт BOB, не подтверждённый баланс кабинета; расходы синтетических опытов вне производственного счётчика.

До активации нужны ключ/защищённый маршрут, подтверждённый бесплатный пакет и флаги `GIGACHAT_ENABLED`, `GIGACHAT_FREE_CONFIRMED`, `GIGACHAT_TRANSPORT_VERIFIED`, `GIGACHAT_EVALUATED`, плюс положительный cap. Личный режим ограничен владельцем; остальным также требуется `GIGACHAT_PUBLIC_USE_CONFIRMED=true` после выяснения соответствующих условий. Отсутствие необходимых условий закрывает интерфейс и резерв.

[Соглашение, показанное при создании проекта, п. 3.1](https://developers.sber.ru/docs/ru/policies/gigachat/agreement) и [условия Freemium API, п. 2.4](https://developers.sber.ru/docs/ru/policies/gigachat-agreement/individuals) описывают личное некоммерческое использование. Это не подтверждение допустимости общей альфы для неограниченного круга участников. До выяснения публичное использование не включается; ключ никому из участников не выдаётся. Бесплатный хостинг не снимает это ограничение.

## Проверки

`tests/gigachat.test.mjs` проверяет native v2, запреты функций/аргументов/смешанных пакетов, OAuth/cache/refresh, таймауты, фактические токены, отказ до сети, один поток и пакет между днями. `tests/gigachat-node.test.mjs` — изоляцию CA, фиксированные цели, TLS, отказ редиректов/подмены адреса, размер и обрыв ответа. В workerd SQLite проверяется consent → OAuth → v2 → проверка → запись → отдельные токены, Telegram replay и сохранение Cloudflare у другого пользователя. Внешние API workerd подменены.

`scripts/check-gigachat-live.mjs` использует только синтетические данные и `Assistant.prepare`, не исполняет действия, сохраняет число HTTP-генераций и резерв до отправки, не допускает перезапуска для сброса лимита текущего опыта. Для Ultra предусмотрен отдельный журнал и явный `--ultra-validation`; запускать только после разрешения на его пределы.
