# GigaChat для планирования — bob-wrh.24

Проверено 6 ноября 2026. Реализован адаптер, но живой GigaChat **не включён**: аккаунт и пакет ещё не получены, транспорт из Cloudflare не проходит проверку сертификата, качество на реальном API не оценено. Тесты с подменой API этого не доказывают.

## Контракт приложения

`src/gigachat.mjs`: OAuth Basic с `GIGACHAT_API_PERS`, UUID RqUID, 30-минутный access token только в памяти, refresh за минуту до истечения и один повтор после HTTP 401. Адрес авторизации фиксирован: `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`. Генерация — `https://api.giga.chat/v1/chat/completions`, модель Lite `GigaChat-2`. Таймаут ограничен общим временем хода; ошибки не раскрывают ответы провайдера или ключи.

Нативный API v1 предлагает одну функцию. `propose_actions` содержит от одного до пяти предложений `{name, arguments_json}`. JSON-строка аргументов проходит существующие `decodeCalls`, схему инструментов и `Assistant.prepare`: даты разбираются кодом, проверяются выбор дела, права, длительность и пакетность. Модель не исполняет действия напрямую. `reply_user` не доступен. Локальные команды, простые действия и фильтр непрофильных запросов работают до любого провайдера.

Cloudflare остаётся по умолчанию. Выбор GigaChat — отдельное, одноразовое, привязанное к пользователю согласие в `/providers`; можно отключить. Передаются текст просьбы и ограниченный контекст планирования, указанный в форме согласия. Нет автоматического переключения после ошибки, исчерпания квоты или отключения провайдера.

## Квоты и активация

Отдельный централизованный `ProviderLedger` считает токены, а не neurons: общий предел BOB 500 000 в UTC-сутки, личный 20 000 в сутки и 100 запросов, пожизненный лимит пакета `GIGACHAT_TOKEN_CAP`. Пакет **не восстанавливается** в полночь. Разрешён один незавершённый запрос GigaChat во всём BOB. До отправки резервируется консервативная верхняя оценка UTF-8 bytes + output limit + запас. После ответа списывается `usage.total_tokens`; при неизвестном результате — весь резерв. Наблюдаемый расход может превышать оценку и записывается целиком. Это защитный учёт BOB, не подтверждённый баланс кабинета. Посторонние приложения могут тратить тот же пакет.

`scripts/deploy.mjs` сохраняет опциональный `GIGACHAT_AUTH_KEY` в secret binding. Нужны **все** флаги:

- `GIGACHAT_ENABLED=true`;
- `GIGACHAT_FREE_CONFIRMED=true` — бесплатный пакет реально виден в аккаунте;
- `GIGACHAT_PUBLIC_USE_CONFIRMED=true` — условия допускают работу общего бота;
- `GIGACHAT_TRANSPORT_VERIFIED=true` — проверен защищённый маршрут из рабочего Worker;
- `GIGACHAT_EVALUATED=true` — реальные русскоязычные сценарии проходят проверку;
- положительный `GIGACHAT_TOKEN_CAP`, не больше остатка Lite-пакета.

Отсутствие любого флага или ключа закрывает и интерфейс выбора, и внутренний резерв. Deploy не включает их сам. Ключи в `.env` исключены из Git; `CALENDAR_SECRET_KEY` сохраняется при обновлении.

## Подтверждённые ограничения

6 ноября диагностический POST `/admin/providers/connectivity` из опубликованного Worker без ключей/пользовательских данных получил **526** и для `api.giga.chat`, и для OAuth. [Документация GigaChat](https://developers.sber.ru/docs/ru/gigachat/certificates) требует корневой сертификат НУЦ Минцифры. В [Workers node:https](https://developers.cloudflare.com/workers/runtime-apis/nodejs/https/) пользовательский `ca` не поддерживается. Отключать TLS-проверку нельзя. Возможное решение — отдельный управляемый Node-сервис с CA, ограниченным этим приложением, и аутентифицированным HTTPS-маршрутом; собственного доступного хоста пока нет, такой сервис не развёрнут.

[Условия Freemium, п. 2.4](https://developers.sber.ru/docs/ru/policies/gigachat-agreement/individuals) ограничивают использование личными некоммерческими целями. Это не подтверждение права обслуживать неограниченный круг пользователей; до выяснения публичный режим GigaChat закрыт. Передавать ключи пользователям нельзя. [Тарифы](https://developers.sber.ru/docs/ru/gigachat/tariffs/individual-tariffs) и [быстрый старт](https://developers.sber.ru/docs/ru/gigachat/individuals-quickstart) отдельно описывают изменение покупки пакетов для новых клиентов с 1 сентября 2026. Нельзя обещать новому аккаунту старый бесплатный пакет без проверки кабинета, подключать оплату или объединять аккаунты ради обхода квот.
