# BOB: проверка настоящего Workers AI API

Дата: 4 ноября 2026 года. Задача: `bob-wrh.2`.
Статус: API-проверка выполнена. Это экспериментальное ядро и рекомендация для прототипа; Telegram-бот и облачная база продукта ещё не развёрнуты.

## Главный результат

С разрешения пользователя создан API-токен `BOB API evaluation`: Workers AI Read/Edit, только текущий аккаунт. Он хранится в локальном D:\Assistant_BOB\.env, исключённом из Git. Значение не включается в отчёты, исходники и журналы. Workers Free сохранён, платные тарифы/модели не подключались.

Настоящий авторизованный API работает. Повреждения из публичного playground в прямых нестриминговых ответах не повторились. Проверены реальные JSON Schema-запросы и tool_calls, а не только инструкция «напиши JSON».

Техническая рекомендация агента: GLM-4.7-Flash с отключёнными рассуждениями для первого диалогового прототипа. Причина: рабочая нативная история результатов функций, успешная последовательность создания/исправления/завершения и более низкий расход. Это не утверждение, что пользователь уже выбрал модель навсегда.

## Что реализовано

В `experiments/workers-ai/` находятся:

- HTTP-клиент Workers AI compatible API, дополнительный native-адаптер и режимы smoke/all/dialogue.
- Корпус из 24 вымышленных русскоязычных сценариев: даты, границы месяца/года, несколько задач, фокус предыдущего разговора, конфликты, отсутствие данных, часовые пояса, повторы и инструкции внутри импортов.
- Два протокола функций: общий submit_plan и отдельные предметные инструменты create_task/create_event/update_task/update_event/complete_task/plan_session/list_tasks/list_events/ask_user/explain_infeasible.
- Изолированная SQLite-база с транзакциями и защитой от повторного исполнения запроса.
- Проверка схемы, существования/владельца объекта, неоднозначности, полномочий на изменение срока, занятости, размера рабочего интервала и допустимости календарных дат.
- Удаление напоминаний при завершении задачи, запрет частичной записи ошибочного пакета.
- Дополнительные проверки обнаруженных ошибок: неизвестное время дедлайна не превращается в полночь; один явно названный срок не теряется/не меняется; явно названное время срока сохраняется; серия «начиная с завтрашнего дня» не начинается в произвольную дату.
- 27 локальных регрессионных тестов; все прошли.

Последние правила дат покрывают конкретный поддержанный поднабор русского ввода. Это не универсальный разборщик естественного языка. В продуктивном ядре нужно расширить разрешение дат и обрабатывать неподдержанное уточнением/предварительным показом записи.

## Сравнение моделей

Первый протокол с общим submit_plan дал Qwen 18/24, GLM 6/24, Mistral 15/24. Затем функции разделены по предметным действиям. В следующем протоколе тот же корпус и общие настройки: temperature=0.1, max_tokens=1536, stream=false. GLM и Gemma использовали свой документированный параметр enable_thinking=false; у Qwen режим рассуждений оставлен по умолчанию.

| Модель | Совпало с ожидаемым первым шагом из 24 | Медиана одного tool API-вызова | Средний расход одного tool-вызова |
|---|---:|---:|---:|
| Qwen3-30B-A3B-FP8 | 20 | 2,68 с | 24,88 neurons |
| GLM-4.7-Flash | 18 | 1,59 с | 13,68 neurons |
| Gemma 4 26B A4B | 17 | 1,43 с | 18,22 neurons |
| Mistral Small 3.1 24B | 15 | 1,35 с | 74,54 neurons |

Это узкий однократный синтетический набор и строгий полевой критерий первого шага, а не общая точность моделей. Некоторые несовпадения безопасны: объяснение невозможности вместо ожидаемого уточнения. Другие существенны: неверная дата, потеря времени или попытка изменить неоднозначный объект. Задержки измерены с локального компьютера; это не обещание скорости Telegram-бота.

JSON Schema smoke-проверка во втором протоколе прошла у трёх исходных моделей. У Gemma структурированный ответ был корректен по форме, но содержал лишнее уточнение вместо ожидаемого действия. Корректная схема не гарантирует корректный смысл.

## Проверка настоящего диалога

Для GLM выполнены три связанных API-вызова с одной общей тестовой базой и реальными результатами функций:

1. «Добавь задачу: подготовить демо к 12 ноября. Время сдачи не указано» — создана запись со сроком 2026-11-12.
2. «Перенеси её сдачу на 14 ноября. Дата без времени» — изменена именно эта запись.
3. «Всё, сделал — отметь выполненной» — та же запись получила completed=1, срок остался 2026-11-14.

Все три шага прошли. Прочие задачи и чужая запись не изменились.

Qwen в отдельных попытках теряла срок из первого сообщения. После добавления проверки такой ответ отклонялся до записи. Совместимый API Qwen дважды ответил HTTP 400 при передаче нативной истории tool-role сообщений; нормализация assistant content в null проблему не устранила. Проба с текстовым представлением истории избавилась от HTTP 400, но восстановление после ошибки исчерпало лимит ответа и не завершилось. Поэтому нативный диалоговый путь Qwen пока не выбран, несмотря на лучший результат отдельных запросов. Успешное автоматическое восстановление после ошибки для неё не заявляется.

## Перепроверка ограничений без новых API-запросов

Сохранённые планы повторно пропущены через усиленные проверки. Исходные API-оценки выше не переписывались.

- Qwen: 1 план отклонён; несовпавших с узким эталоном действий, совершивших запись, не осталось.
- GLM: 6 планов отклонены; несовпавших записей по этому эталону не осталось.
- Gemma: 3 плана отклонены; несовпавших записей по этому эталону не осталось.
- Mistral: 5 планов отклонены; остались 3 несовпавшие записи в сценариях создания/переноса даты. Для автоматических записей она не рекомендована.
- Ни один отклонённый план ни в одном варианте не изменил тестовую базу.

Это анализ сохранённых ответов после добавления проверок, а не новый независимый тест качества. Контроль владельца, readOnly, candidateIds, resolvedId и разрешения на смену дедлайна задаются приложением/тестовыми данными, а не выводятся исполнителем из произвольного текста. В реальном приложении их ещё нужно правильно формировать. Нулевой результат на этих примерах не является общей гарантией безопасности.

## Бесплатный бюджет

Выполнен 191 API-запрос: первичные проверки, два сравнительных прогона и диалоговые пробы. 189 ответов содержали usage.neurons; их сумма — **5509,76 neurons**. Два HTTP 400 не содержали расхода. Локальный консервативный счётчик, резервирующий возможный расход и для неизвестных исходов, — **5717,87** при пределе 6000. Это запросная телеметрия API, а не отдельная сверка платёжного кабинета.

Публичный Free-лимит — 10 000 neurons в сутки на весь Workers AI. Расход суммируется между моделями, поэтому переключение модели не восстанавливает исчерпанную общую квоту.

По среднему расходу GLM в этом наборе 30 обращений по два похожих вызова — около **821 neurons/сутки**. Это сценарная оценка по измеренным коротким запросам, не гарантированное число сообщений: длинная история, сводки, дополнительные шаги и другие входные данные изменят расход.

Для прототипа: короткий контекст из базы, обычно один вызов на простую операцию, ограничение дополнительных шагов/повторов, дневной резерв. При недоступном ИИ или общей квоте остаются обычные команды, обзоры и уже сохранённые напоминания; автоматический переход на платную модель не допускается.

## Воспроизведение

Node.js 24, без сторонних npm-зависимостей. Из D:\Assistant_BOB:

```powershell
node --test experiments/workers-ai/tests/*.test.mjs
node experiments/workers-ai/scripts/evaluate-ai.mjs --stage describe
node --env-file=.env experiments/workers-ai/scripts/evaluate-ai.mjs --stage smoke --models glm --tool-style domain --budget 6000
node --env-file=.env experiments/workers-ai/scripts/evaluate-ai.mjs --stage all --models glm --tool-style domain --budget 6000
node --env-file=.env experiments/workers-ai/scripts/evaluate-ai.mjs --stage dialogue --models glm --tool-style domain --budget 6000
```

Дневной счётчик сохраняется в experiments/workers-ai/work. Повторные команды выполняют новые запросы и расходуют квоту, пока хватает локального резерва. При ошибках авторизации/дневной квоты прогон останавливается. Нельзя запускать несколько экземпляров эксперимента параллельно: межпроцессная блокировка счётчика ещё не реализована.
