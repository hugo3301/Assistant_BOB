# BOB: варианты реализации при бюджете около нуля

Дата проверки источников: 2026-11-04. Связано с `bob-wrh` и `requirements.md`.
Статус: предложения для обсуждения; стек пользователем не выбран. Пользователь вошёл в Cloudflare; текущий план Free проверен через UI. Авторизованный Workers AI API проверен; локальное диалоговое ядро реализовано в bob-wrh.3 (docs/dialogue-core.md). Telegram и постоянное развёртывание пока не настроены. Актуальное предложение по важному для пользователя ИИ-диалогу: `ai-design.md`; аудит и пробы: `hypothesis-review.md`, `ai-evaluation.md`.

## Общая схема

Telegram → обработчик команд и сообщений → база обязательств, расписания, проектов и настроек.
Периодический запуск → выборка наступивших напоминаний → отправка сообщений в Telegram.
Языковая модель как основа диалога → разбор свободного текста и предложения плана; изменения с неоднозначностью требуют уточнения.

Хранить события, задачи, проекты, повторения и исходные идентификаторы импортированных занятий. Дедлайн, время события и момент начала подготовки различать. Сохранять очередь напоминаний и результаты отправки в базе; предусмотреть повторные попытки, защиту от обычных дублей, обновление при переносе и явное поведение для пропущенных уведомлений. Абсолютную однократность доставки через внешнее API без дополнительных гарантий не обещать.

Напоминания, команды обзоров и импорт календаря могут работать без языковой модели. Для первой версии доступен структурированный ввод через кнопки/короткие формы. Гибкое понимание произвольных сообщений и оценка плана требуют отдельной проверки модели; кнопки и базовые функции должны сохраняться при её недоступности.

## Вариант A: существующий компьютер

Предложение: Python, SQLite, Telegram long polling, локальный процесс проверки напоминаний.
Нет обязательной платы за хостинг, если устройство уже имеется. Электроэнергия и интернет остаются расходами. Процесс требует работающего устройства и сети; сон или выключение прервут своевременную отправку. Нужны автозапуск, восстановление после сбоя и копии базы.
Это простой локальный прототип, но выбор для постоянного использования зависит от наличия устройства, работающего круглосуточно.

## Вариант B: бесплатные облачные функции

Кандидат: TypeScript + Cloudflare Workers + D1 + Cron Triggers, Telegram webhook.
Workers выполняет короткие обработчики по входящим сообщениям и по расписанию; компьютер пользователя можно выключать. D1 хранит данные между запусками.

По текущим первичным источникам:
- Telegram Bot Platform бесплатна для обычного использования ботов.
- Workers Free: 100 000 запросов/день, 10 мс CPU на обработчик; старт без банковской карты заявлен на странице продукта.
- D1 Free: 5 млн прочитанных и 100 тыс. записанных строк в сутки; максимальный размер одной базы — 500 МБ.
- Cron Triggers допускает запуск каждую минуту и использует UTC; пользовательский часовой пояс нужно преобразовывать явно. Это минутная проверка, а не обещание доставки в точную секунду.

Предварительная оценка: объём обычных операций одного пользователя должен укладываться в бесплатные квоты при индексированных запросах и небольших порциях работы. Это оценка, а не результат нагрузочной проверки. В частности, импорт реального iCalendar, обработку повторений и генерацию обзоров нужно замерить относительно лимита CPU; при необходимости разбивать обработку на части.

На Free при исчерпании квот возможны ошибки и остановка операций; это не гарантия вечной бесплатности или бесперебойности. Перед выбором проверить регистрацию/доступ, приём Telegram webhook, отправку сообщений и регулярные срабатывания. Платные планы автоматически не подключать.

## ИИ: важная часть интерфейса с независимым хранением и напоминаниями

Workers AI предоставляет 10 000 neurons в сутки на Free. Это единицы вычислений, не количество сообщений; расход зависит от модели и длины контекста. Некоторые модели требуют оплаты, поэтому отбирать только доступные на Free. Проверить русский язык, извлечение дат и расход на реальных примерах. При исчерпании квоты ИИ отключается до восстановления лимита, а обычные команды и напоминания продолжают работать, если их собственные квоты доступны.

Локальная модель — другой возможный путь без оплаты запросов; пригодность зависит от имеющегося оборудования, скорости и качества. Пока модель и оборудование не изучены.

## Предлагаемая последовательность проверки

Сначала проверить реальный API моделей, затем небольшую полную цепочку: Telegram, понимание сообщения ИИ, контролируемое сохранение/исправление задачи, восстановление состояния и отправка по таймеру. Затем — реальный iCalendar и фильтрация своих пар, обзоры и переносы. Первичные пробы публичного playground уже проведены, но их повреждённые ответы не заменяют API-проверку. Это предложение последовательности, не разрешение на реализацию или развёртывание.

Beads используется для разработки BOB. Пользовательские обязанности предполагается хранить в собственной базе помощника.
