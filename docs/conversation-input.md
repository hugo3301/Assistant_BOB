# Разговорный ввод BOB

4 ноября 2026, `bob-wrh.7`. Исправление по первому личному использованию альфы.

Бот принимает разговорные фразы о занятиях без обязательного «добавь», слова вокруг времени и оформление Markdown. Например: «сегодня вечером где-то к 7 вечера пара по предмету есть», «в 7 вечера», «к семи вечера», «завтра в 19.30», «через полчаса», «в полседьмого вечера», «12-го ноября». День недели, относительные интервалы и календарные даты вычисляет программа. «Следующая пятница» означает пятницу следующей календарной недели, «ближайшая» — ближайшую подходящую дату; результат всегда показан в ответе.

Короткое уточнение заменяет неудачную фразу времени и дополняется днём из исходного сообщения. Новый явно начатый запрос, в том числе после Markdown `>`, прекращает прежнее уточнение. Словесные числа и 12-часовые обозначения преобразуются кодом; 7 вечера — 19:00. Неполное «вечером» вызывает вопрос о времени, а не требование написать дату по шаблону.

Если для новой встречи явно названо время, но день отсутствует, берётся сегодня и показывается полная дата. Прошедшее время не переносится на завтра молча. «Около/примерно/где-то» сохраняется отдельным признаком в базе и отображается в обзорах/напоминаниях. Дедлайн без времени остаётся датой. Конфликтующие даты/часы, неизвестный год прошедшей даты, несуществующее время и неподдержанные интервалы уточняются. Выдуманную ISO-дату и неверный час нельзя легализовать одним ответом модели.

Проверка: 101 регрессионный тест (включая 33 новых примера разговорного ввода и уточнений), workerd с SQLite Durable Object и полным перезапуском. Четыре независимых живых сценария GLM прошли: разговорное вечернее занятие, вопрос о времени с коротким ответом, Markdown-цитата задачи, встреча в полседьмого. 4 API-вызова, 48.6151 neurons; недостающее время уточнено без дополнительного модельного вызова. Данные проверок синтетические/обезличенные, рабочая база пользователя не изменялась. Это расширение поддержанного языка, не гарантия понимания любой фразы.

## Длительность работы: bob-wrh.20, 5 ноября 2026

«Час поработать», «полчаса поработать», «два часа поработать», «поработать полтора часа», «на 45 мин» и «на 2 часа 30 минут» распознаются кодом. Поддержаны составные словесные числа. Программа берёт длительность из исходного текста, не из предложенного моделью числа; время работы не меняет внешний срок сдачи задачи.

«В час», «через час» и «за час» сами по себе не задают длительность. Перенос «на час раньше» не превращается в часовое занятие. Диапазоны/альтернативы и неоднозначные числовые последовательности требуют уточнения; неизвестная длительность не выдумывается. Базовый экспорт durationFromText сохранён, реализация вынесена в src/duration.mjs.

30 профильных проверок и все 269 Node-тестов прошли. Настоящий workerd SQLite проверил полный путь синтетического запроса: создан один часовой рабочий интервал, дедлайн родительской задачи сохранён; внешние API подменены. Переход с текущей опубликованной сборки сохраняет дело, историю, ожидающий ответ и учёт расхода. Это исправление причины DURATION_MISSING, обнаруженной в эксперименте free-ai-options.md; сравнительный эксперимент моделей целиком не повторялся.
