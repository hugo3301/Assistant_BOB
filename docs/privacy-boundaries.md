# Границы передачи данных BOB

Проверка 7 ноября 2026. Отсутствие найденной утечки не означает гарантии отсутствия всех уязвимостей или доступа операторов хостинга к своей инфраструктуре.

| Участок | Что передаётся | Защита |
| --- | --- | --- |
| Telegram → Worker | Текст либо идентификатор файла, время/размер записи, необходимые ID для ответа | Проверка webhook secret, отправителя и личного чата; в очередь попадает только разрешённый набор полей. Контакты, данные пересылок, лишние поля профиля и исходное сообщение кнопки не копируются |
| Worker → текстовая модель | Текущая просьба, время/зона, только совпавшие дела для изменения/ссылки на существующее дело | История диалога и несвязанные дела не отправляются. Права и итоговые действия проверяет приложение. Ключи из ввода/контекста/предложенных аргументов блокируются до дальнейшей передачи/записи |
| Telegram → STT | Аудио для выбранного пользователем распознавания | Ограничения размера/реальной длительности, отдельный бюджет, согласие на Groq. Если после STT распознан ключ, расшифровка не кешируется и не цитируется в ответе. Проверить содержимое речи до распознавания бот не может |
| Worker → Netlify → GigaChat | Минимизированный модельный запрос | GigaChat доступен только владельцу по выбору; HMAC, срок запроса и однократный durable claim. Ключ GigaChat только в секрете Netlify, ключи Telegram/календарей туда не передаются. Функция не пишет тела/ключи в свои логи; транспорт Node проверяет TLS и разрешает фиксированные адреса |
| Google OAuth / Яндекс CalDAV | Авторизация на специальных страницах и события выбранного календаря | Ограниченные Google scopes, PKCE/state, browser cookie и Origin, короткие одноразовые setup tickets; AES-256-GCM с привязкой к владельцу и подключению. Фиксированные адреса OAuth/API; Яндекс-переходы допускаются только внутри разрешённого HTTPS-хоста |
| Worker → Telegram | Ответы, напоминания, личный экспорт | Разрешён только личный адрес владельца tenant. Распознанные/известные ключи маскируются перед отправкой текста/файла; после маскирования сбрасываются устаревшие offsets entities |
| Панель / календарь Mini App | Личные дела своему пользователю; эксплуатационные агрегаты только владельцу | HMAC Telegram initData, срок подписи, проверка доступа/владельца, same-origin POST, no-store, CSP, экранирование HTML. В метриках нет имён, Telegram ID участников, названий дел и сообщений |
| GitHub CI/CD | Исходники; только отдельный deploy token в production environment | Приложенческие ключи не загружаются в GitHub. CI без production secrets, закреплённые Actions, публикация только проверенного текущего main. Для новых коммитов — публичный GitHub noreply |

Текстовая модель, выбранное распознавание и подключённый календарь по назначению получают необходимые личные данные: это обработка в этих сервисах, а не публичная публикация. BOB не является хранилищем паролей. Распознавание секретов основано на известных серверу значениях и форматах; произвольный неизвестный пароль без признаков ключа не всегда можно отличить от обычного текста.

Для Telegram, Workers AI и Groq отключено автоматическое следование HTTP redirects с телами/ключами; у календарей и GigaChat уже применялся manual redirect / список разрешённых адресов. Ответы JSON этих сервисов ограничены по размеру, переполнение прекращает чтение. Сырые ошибки провайдера не возвращаются пользователю.

Результаты аудита: в 210 отслеживаемых файлах, 659 доступных Git-объектах и публикационных артефактах не найдены известные действующие секреты. GitHub secret-scanning и push protection включены, открытых secret/dependency alerts нет. Проверены 19 запусков Actions: 17 журналов доступны и не содержат проверяемых ключей, два журнала недоступны. Публичных Issues и загруженных Actions artifacts нет. npm audit — 0 известных уязвимостей. Независимый Gitleaks выявил имя переменной конфигурации в документации; оно проверено как ложное срабатывание, не значение ключа.

В старых метаданных Git есть адрес автора, отличающийся от контакта публичного GitHub-профиля. Значение здесь не воспроизводится. Изменение будущего автора не убирает старые коммиты; переписывание опубликованной истории требует отдельного решения и не стирает чужие копии/кеши. [Об удалении чувствительных данных из GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).

Проверки инфраструктурных кабинетов ограничены имеющимся доступом: закрытые логи/резервные копии самих провайдеров не выгружались. Новые аккаунты/ключи не создавались, реальные пользовательские генерации/STT и синхронизационные изменения для аудита не запускались. Общие рекомендации по исключению секретов из журналов: [OWASP Logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html), [OWASP Secrets Management](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html).
