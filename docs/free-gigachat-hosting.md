# Бесплатное размещение моста GigaChat

Проверено 6 ноября 2026, bob-wrh.26. Пользователь просит найти постоянное бесплатное размещение вместо своего постоянно включённого компьютера. Новые аккаунты хостинга не создавались, ключ GigaChat ни одному из перечисленных хостеров не передавался.

## Рекомендация

Для небольшой некоммерческой альфы первый кандидат — **Vercel Hobby, Node.js Function**. Нужен короткий HTTPS-запрос к GigaChat с собственным CA, а не круглосуточный фоновый процесс. Основной Worker, SQLite, очереди, напоминания и Telegram остаются в Cloudflare. Функция запускается по реальному запросу; искусственные keep-alive не нужны. Это вывод из возможностей платформы, ещё не проверенное развёртывание данного проекта.

| Вариант | Бесплатные условия и ограничения | Вывод |
| --- | --- | --- |
| Vercel Hobby | 1 млн function invocations, 4 CPU-часа, 360 GB-часов памяти за месяц; личные некоммерческие проекты. При превышении квот функциональность приостанавливается. | Подходит по модели работы для маленького моста; нужен живой тест CA/сети, аккаунта и холодного старта. |

Нужен вход в панель раз в 120 дней в первый год. | По ресурсам хватило бы; не выбираем как вариант без карты. Отдельные непрерывные фоновые services ограничены. |

Ни один free-план не является гарантией бесплатной работы навсегда или SLA. Подтверждённая работоспособность API из локального Node не доказывает доступность из региона нового хостинга. Не обходить региональные/платёжные ограничения и не создавать дополнительные аккаунты ради квот.

## Условия перед подключением

Нужен отдельный ограниченный мост: только GigaChat и выбранная бесплатная модель, проверка подписи/срока запроса, защита от повторов и контроль квоты до отправки. Он не должен быть открытым универсальным прокси. Корневой CA применяется только к конкретным запросам GigaChat, без изменения системного доверия или отключения TLS. В `src/gigachat-node.mjs` уже есть такой ограниченный исходящий транспорт; это **не готовый публичный HTTP-мост**.

Развёртывать мост имеет смысл после успешной проверки модели. Затем потребуются аккаунт выбранного хостера и отдельное согласие на передачу туда ключа GigaChat и выбранного контекста. Нужны отдельные секреты связи, ограничения логов и измерение времени первого запроса. Текущие ключи Telegram, календарей и Cloudflare хостеру не нужны.

Личные условия GigaChat также требуют отдельной проверки применимости к публичной альфе. Бесплатный план хостинга сам по себе не разрешает расширять использование API. До выяснения этого вопроса нельзя включать GigaChat для всех участников.
