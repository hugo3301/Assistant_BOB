# BOB alpha: сервер и Telegram

Дата: 4 ноября 2026. Beads: `bob-wrh.4`. Бот: [@mybob_robot](https://t.me/mybob_robot). Сервер: `assistant-bob-alpha`, Cloudflare Workers Free. Постоянное хранилище — SQLite-backed Durable Object `BobObject`; отдельная D1 не создавалась. Код ядра общий с локальной Node SQLite, адаптеры хранения различаются.

## Объём альфы

Свободный текст через GLM создаёт задачи/встречи и изменяет сохранённые записи; фокус и уточнения остаются в базе. Даты, владельца, цель и допустимость изменения срока проверяет приложение. Результат записи подтверждает код. Большие списки лучше присылать порциями до пяти действий. Неподдержанные даты уточняются; произвольный русский ввод не считается полностью проверенным.

Команды `/today`, `/week`, `/ahead`, `/tasks`, `/find текст` работают без ИИ. Внизу чата есть кнопки с основными командами. `/ahead` охватывает все известные открытые сроки и дела без даты. Это помогает увидеть редкие обязательства, если пользователь уже внёс их в BOB; неизвестные обязанности бот не может восстановить сам.

`/project Название` создаёт/выбирает проект для новых дел. `/project off` отключает выбранный проект. `/area Учёба` выбирает категорию; доступны Учёба, Проекты, Зал, Питание и Личное. `/projects` показывает проекты и остальные категории, количество открытых дел и сами дела с датами/без дат. Привязка уже созданных дел к другому проекту пока не вынесена в интерфейс.

`/repeat пн,ср,пт 18:00 60 Зал` создаёт еженедельную серию по часу. Команда лишь пример: фактические дни/время зала пользователя неизвестны, поэтому тренировки автоматически не добавляются. Ближайшие шесть недель материализуются в события и пополняются сервером. `/repeats` показывает серии; `/repeat stop id` останавливает серию и отменяет будущие вхождения. Отмена отдельного вхождения через `/remove id` сохраняет исключение: повторное пополнение его не воссоздаёт. Полное RFC-управление сериями/«всё начиная с этой даты» не реализовано. Модель не создаёт повторения свободным текстом; бот подсказывает команду.

`.ics` принимается файлом до 1 МБ. Личный календарь с одной группой импортируется сразу. Для смешанного файла достаточно один раз ответить «все мои», «только 1 и 3» или указать свою подгруппу; затем фильтр применяется автоматически при повторной загрузке. Новые неизвестные группы требуют уточнения. Обрабатываются даты, повторы, EXDATE, явные отмены и напоминания, повторная загрузка не дублирует записи. Подробности, проверки и границы — docs/calendar-import.md. Настоящий файл ТПУ ещё не предоставлен.

`/diet свой текст` хранит существующий рацион пользователя, `/diet` показывает его. Бот не подменяет его выдуманным меню и не даёт медицинских рекомендаций. Состав рациона пока не получен.

`/done id` завершает задачу, `/remove id` отменяет дело и напоминания. `/export` присылает JSON-файл с пользовательскими данными без ключей доступа. Автоматическое восстановление из экспорта ещё не реализовано; это выгрузка, не проверенный backup/restore.

## Доступ и секреты

Входящий webhook проверяет отдельный случайный secret header; принимаются личные сообщения активных участников по приглашениям (до 10 вместе с владельцем). ControlObject проверяет доступ и бюджет; отдельный BobObject хранит дела каждого участника. Неприглашённые пользователи и группы не передаются модели. Public `/health` показывает только сервис/версию, `/admin/status` требует отдельный случайный секрет и возвращает счётчики без текстов дел.

Токен @mybob_robot и существующий Workers AI токен находятся в серверных secret bindings. Ключ развёртывания не загружается в Worker. Первый `BOB alpha deploy` истёк 5 ноября 2026 в 08:00 по Томску; две попытки продления через UI не сохранились, API подтвердил прежний статус expired. После отдельного разрешения пользователя создан `BOB alpha deploy replacement`: Workers Scripts Edit, Account Settings Read, только текущий аккаунт, окончание 5 ноября 2026 в 14:00 по Томску (07:00 UTC), проверенное через API. Новый ключ заменил CLOUDFLARE_DEPLOY_TOKEN в исключённом .env; одноразовые файлы передачи удалены. Истечение ключа не отключает опубликованного бота; для последующих публикаций потребуется новый разрешённый доступ.

Локальные ключи — только в исключённом `.env`. `/work/`, `.dev.vars`, `.wrangler` и node_modules исключены из Git. Промежуточный JSON секретов для атомарного deploy удаляется в finally. Логи приложения не включают токены/тексты сообщений; ошибки сети сохраняются общими кодами. Само пользовательское состояние, ответы для повторов и текст ожидающих работ хранятся в SQLite Cloudflare. Сообщения, ограниченный контекст дел и история передаются Workers AI. После успешной обработки сырой Telegram payload в очереди очищается. Сквозное шифрование личной базы не реализовано.

## Серверная обработка

Webhook только сохраняет update в постоянную очередь и будит alarm; длительного ожидания ИИ в Telegram HTTP-ответе нет. Update id уникален. Alarm обрабатывает очередь по порядку, ядро атомарно сохраняет пользовательское действие и его результат. Затем формируется постоянный outbox ответа. Сбой между этими этапами восстанавливается из сохранённого результата без повторной записи. Отправка делится на сообщения до 3500 символов; подтверждённые части повторно не отправляются при обычной повторной обработке update.

Необработанная работа получает аренду и ограниченные повторы, outbox — повтор с учётом Telegram retry_after. После восьми неудач ответ остаётся failed. Отправка напоминаний имеет отдельные аренды, до пяти попыток и также учитывает retry_after. `/status` показывает счётчик недоставленных напоминаний. После сбоя между внешним подтверждением Telegram и записью sent возможен дубль: exactly-once не обещается.

Новые jobs запускаются сразу. Alarm планируется по ближайшей работе с часовым обслуживанием; Cron `* * * * *` проверяет общий реестр и будит только участников с наступившей работой. Cron может отправить сохранённое напоминание, пока другой ход ждёт ИИ; недоступность ИИ не выключает очередь. Фактическая доставка зависит от квот, платформы и Telegram, секунда в секунду не гарантируется. Известные истёкшие события/рабочие интервалы получают статус elapsed; событие с неизвестной длительностью скрывается из открытого списка через сутки после старта, задачи сами не закрываются.

Пользователь подтвердил: Asia/Tomsk, сводка 08:00, напоминание за 60 минут. `/settings`, `/morning HH:MM|off`, `/timezone IANA`, `/remind минуты` меняют настройки. Изменение часового пояса сохраняет абсолютный UTC-момент уже созданных встреч; серии сохраняют исходный часовой пояс. Сводка после пропущенного запуска догоняется в течение восьми часов, после этого пропускается.

## Бюджет

Workers Free оставлен без платного апгрейда. Фиксирована GLM-4.7-Flash без thinking и платного fallback. Общий дневной предел приложения — 9000 neurons, личный — 800; резервирование до запроса и итоговый учёт выполняет ControlObject. Предыдущий серверный расход переносится однократно. Free аккаунта даёт 10000 в UTC-день, без накопления на месяц. Подробности и расчёт нагрузки: multi-user-budget.md. Чужие приложения в аккаунте требуют отдельного учёта.

SQLite-backed Durable Objects доступны на Free. При превышении бесплатных лимитов соответствующие операции прекращаются, автоматический платный переход не включён. Источники: [DO pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/), [DO SQLite API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/), [alarms](https://developers.cloudflare.com/durable-objects/api/alarms/), [Workers AI GLM](https://developers.cloudflare.com/workers-ai/models/glm-4.7-flash/), [Telegram Bot API](https://core.telegram.org/bots/api).

## Обновление: приглашения, голос и единый интерфейс

Доступ по одноразовым приглашениям на 7 дней, максимум 10 человек вместе с владельцем; ожидающие приглашения резервируют места. У каждого свои дела, история, настройки и лимит ИИ. Владелец видит управление приглашениями и числом участников; обычный участник чужие дела не получает. Старый namespace владельца сохранён. Голосовые сообщения до двух минут и 2 МБ распознаются Whisper и проходят тот же путь дат, записей и возврата. Аудио не сохраняется; неуверенное распознавание просит повторить. Настоящие проверки русской синтетической речи и тишины: voice-input.md.

/start открывает новое меню. Новый участник выбирает город кнопкой или пишет название. Настройки сводки/напоминания, проекты и карточки доступны без знания команд; дополнительные функции находятся в справке. Сохранённые предпочтения существующих участников не сбрасываются. /status показывает ошибки доставки, экран ресурса — личный и общий остаток с местным временем обновления. Старые сообщения автоматически не перерисовываются. Подробнее: telegram-design-system.md; каталог 15 экранов: design-catalog.html.

Проверки обновления: 181 Node-тест; настоящий workerd SQLite с десятью изолированными участниками, входом через выбор зоны, повторами/рестартом/429, голосовым файлом и голосовым запросом ресурса (внешние API подменены); переход со старой сборки с сохранением дела, истории, ожидающего ответа и однократным переносом расхода. Каталог визуально проверен в браузере. Это не доказательство месячной нагрузки и не проверенный аварийный backup/restore.
## Обновление: Google и Яндекс в обе стороны

`/calendars` и «Настройки → Календари» подключают по одному календарю Google и Яндекса через личные HTTPS-страницы. Google использует OAuth с calendar.events и calendar.calendarlist.readonly, Яндекс — отдельный пароль приложения «Календарь». Ключи вводятся вне Telegram-чата и не передаются модели. Подробности объёма, защиты, конфликтов и ограничений: calendar-sync.md. Визуальные состояния на вымышленных данных: calendar-connect-preview.html.

Переносятся названия, время/длительность, события на весь день и отмены; внешние серии учитываются по вхождениям. Первичная загрузка охватывает ближайшие 90 дней, обновление обычно раз в пять минут. Одновременные изменения предлагают выбор версии, переподключение сохраняет сопоставление. Старые несвязанные дела и .ics массово не выгружаются; новые встречи направляются только в выбранный календарь по умолчанию. Текущие настройки и namespace владельца сохраняются.

Google Cloud настроен без платного тарифа: Calendar API, веб-клиент с фиксированным callback, ровно два согласованных scope и тестовый доступ владельца. Приложение остаётся Testing: refresh grant для Calendar истекает через семь дней, после чего нужен повторный вход. Личные календари подключает сам участник; автоматические тесты не подтверждают доступ к его реальным событиям.

Проверки: 211 Node-тестов; оба полных пути подключения/импорта/обратной записи в настоящем workerd SQLite с подменёнными внешними API; переход со старой сборки с сохранением дел, истории, ожидающего ответа и однократного учёта расхода. Визуально проверены экраны подключения. Живой аккаунтный пилот обоих провайдеров пока не завершён.
