# BOB alpha: сервер и Telegram

Дата: 4 ноября 2026. Beads: `bob-wrh.4`. Бот: [@mybob_robot](https://t.me/mybob_robot). Сервер: `assistant-bob-alpha`, Cloudflare Workers Free. Постоянное хранилище — SQLite-backed Durable Object `BobObject`; отдельная D1 не создавалась. Код ядра общий с локальной Node SQLite, адаптеры хранения различаются.

## Объём альфы

Свободный текст через GLM создаёт задачи/встречи и изменяет сохранённые записи; фокус и уточнения остаются в базе. Даты, владельца, цель и допустимость изменения срока проверяет приложение. Результат записи подтверждает код. Большие списки лучше присылать порциями до пяти действий. Неподдержанные даты уточняются; произвольный русский ввод не считается полностью проверенным.

Команды `/today`, `/week`, `/ahead`, `/tasks`, `/find текст` работают без ИИ. Внизу чата есть кнопки с основными командами. `/ahead` охватывает все известные открытые сроки и дела без даты. Это помогает увидеть редкие обязательства, если пользователь уже внёс их в BOB; неизвестные обязанности бот не может восстановить сам.

`/project Название` создаёт/выбирает проект для новых дел. `/project off` отключает выбранный проект. `/area Учёба` выбирает категорию; доступны Учёба, Проекты, Зал, Питание и Личное. `/projects` показывает проекты и остальные категории, количество открытых дел и сами дела с датами/без дат. Привязка уже созданных дел к другому проекту пока не вынесена в интерфейс.

`/repeat пн,ср,пт 18:00 60 Зал` создаёт еженедельную серию по часу. Команда лишь пример: фактические дни/время зала пользователя неизвестны, поэтому тренировки автоматически не добавляются. Ближайшие шесть недель материализуются в события и пополняются сервером. `/repeats` показывает серии; `/repeat stop id` останавливает серию и отменяет будущие вхождения. Отмена отдельного вхождения через `/remove id` сохраняет исключение: повторное пополнение его не воссоздаёт. Полное RFC-управление сериями/«всё начиная с этой даты» не реализовано. Модель не создаёт повторения свободным текстом; бот подсказывает команду.

`.ics` принимается файлом до 200 КБ. Сначала формируется список групп по полным SUMMARY/DESCRIPTION/LOCATION; записи не создаются. `/ical keep 1,3` импортирует только выбранные группы на 90 дней. Используется `ical.js`, поддержаны RRULE/EXDATE и исключения, которые распознаёт библиотека. Присутствующие VTIMEZONE используются; стандартный IANA TZID разрешается кодом, floating-время трактуется в профиле пользователя. Неизвестный пояс и событие без точного времени останавливают импорт. Пределы: 500 исходных VEVENT, 5000 шагов расширения, 1000 будущих вхождений. Импорт повторяется без дублей по UID/recurrence-id, существующие открытые вхождения обновляются при изменении. Исчезнувшие из нового файла занятия автоматически не удаляются; нужно отменить их явно. Выбор групп подтверждается при каждой новой загрузке. URL календаря автоматически не опрашивается. С настоящим файлом ТПУ и личными фильтрами пользователя ещё нужна отдельная проверка.

`/diet свой текст` хранит существующий рацион пользователя, `/diet` показывает его. Бот не подменяет его выдуманным меню и не даёт медицинских рекомендаций. Состав рациона пока не получен.

`/done id` завершает задачу, `/remove id` отменяет дело и напоминания. `/export` присылает JSON-файл с пользовательскими данными без ключей доступа. Автоматическое восстановление из экспорта ещё не реализовано; это выгрузка, не проверенный backup/restore.

## Доступ и секреты

Входящий webhook проверяет отдельный случайный secret header; принимаются только личные сообщения с совпадающими sender/chat id настроенного владельца. Id получен из настоящего `/start` и сопоставлен с собственным аккаунтом в Telegram UI. Чужие сообщения и группы не передаются модели и не получают доступ к данным. Public `/health` показывает только сервис/версию, `/admin/status` требует отдельный случайный секрет и возвращает счётчики без текстов дел.

Токен @mybob_robot и существующий Workers AI токен находятся в серверных secret bindings. Ключ развёртывания не загружается в Worker. С разрешения пользователя создан временный `BOB alpha deploy`: Workers Scripts Edit, Account Settings Read, только текущий аккаунт, истечение 5 ноября 2026 в 08:00 по Томску. Истечение этого ключа не отключает опубликованного бота; для последующих публикаций потребуется новый разрешённый доступ.

Локальные ключи — только в исключённом `.env`. `/work/`, `.dev.vars`, `.wrangler` и node_modules исключены из Git. Промежуточный JSON секретов для атомарного deploy удаляется в finally. Логи приложения не включают токены/тексты сообщений; ошибки сети сохраняются общими кодами. Само пользовательское состояние, ответы для повторов и текст ожидающих работ хранятся в SQLite Cloudflare. Сообщения, ограниченный контекст дел и история передаются Workers AI. После успешной обработки сырой Telegram payload в очереди очищается. Сквозное шифрование личной базы не реализовано.

## Серверная обработка

Webhook только сохраняет update в постоянную очередь и будит alarm; длительного ожидания ИИ в Telegram HTTP-ответе нет. Update id уникален. Alarm обрабатывает очередь по порядку, ядро атомарно сохраняет пользовательское действие и его результат. Затем формируется постоянный outbox ответа. Сбой между этими этапами восстанавливается из сохранённого результата без повторной записи. Отправка делится на сообщения до 3500 символов; подтверждённые части повторно не отправляются при обычной повторной обработке update.

Необработанная работа получает аренду и ограниченные повторы, outbox — повтор с учётом Telegram retry_after. После восьми неудач ответ остаётся failed. Отправка напоминаний имеет отдельные аренды, до пяти попыток и также учитывает retry_after. `/status` показывает счётчик недоставленных напоминаний. После сбоя между внешним подтверждением Telegram и записью sent возможен дубль: exactly-once не обещается.

Серверный alarm проверяет очередь не реже примерно минуты, при наличии ближайшей работы — раньше. Cron `* * * * *` служит дополнительным запуском. Cron может отправить сохранённое напоминание, пока другой ход ждёт ИИ; недоступность ИИ не выключает очередь. Фактическая доставка зависит от квот, платформы и Telegram, секунда в секунду не гарантируется. Известные истёкшие события/рабочие интервалы получают статус elapsed; событие с неизвестной длительностью скрывается из открытого списка через сутки после старта, задачи сами не закрываются.

Пользователь подтвердил: Asia/Tomsk, сводка 08:00, напоминание за 60 минут. `/settings`, `/morning HH:MM|off`, `/timezone IANA`, `/remind минуты` меняют настройки. Изменение часового пояса сохраняет абсолютный UTC-момент уже созданных встреч; серии сохраняют исходный часовой пояс. Сводка после пропущенного запуска догоняется в течение восьми часов, после этого пропускается.

## Бюджет

Workers Free оставлен без платного апгрейда. Фиксирована GLM-4.7-Flash без thinking и платного fallback. Локальный дневной предел серверного ИИ — 7500 neurons. В день запуска консервативно занято 6000 neurons под уже выполненные в аккаунте эксперименты; в следующие UTC-дни счётчик начинается с нуля. Это счётчик одной серверной базы, он не видит новые вызовы из других приложений. Эксперименты после запуска должны учитывать общий аккаунтный бюджет.

SQLite-backed Durable Objects доступны на Free. При превышении бесплатных лимитов соответствующие операции прекращаются, автоматический платный переход не включён. Источники: [DO pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/), [DO SQLite API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/), [alarms](https://developers.cloudflare.com/durable-objects/api/alarms/), [Workers AI GLM](https://developers.cloudflare.com/workers-ai/models/glm-4.7-flash/), [Telegram Bot API](https://core.telegram.org/bots/api).

## Разработка и эксплуатация

Из D:\Assistant_BOB:

```powershell
npm.cmd ci --ignore-scripts
npm.cmd test
npm.cmd run test:cloud
npm.cmd run chat
npm.cmd run deploy
node --env-file=.env scripts/server-status.mjs https://assistant-bob-alpha.assistant-bob.workers.dev
```

Wrangler и Miniflare зафиксированы в lockfile; разрешённые бинарные платформенные npm-пакеты уже проверены сборкой. `chat` — отдельная локальная база, не клиент серверной базы. Deploy требует действующего временного ключа в `.env`. Установка службы на Windows не нужна. Никакой Git remote/синхронизации не добавлялось.

4 ноября 2026 пользователь разрешил первоначальную отправку проекта в `https://github.com/hugo3301/Assistant_BOB.git` (`origin`). Git хранит исходники и документацию; `.env`, локальные рабочие данные и база Beads исключены. Резервное копирование Beads и серверных данных этим не настраивается.

Для паузы уведомлений можно выключить утреннюю сводку `/morning off` и отменить дела/серии. Полная остановка при эксплуатации — удалить webhook и отключить серверные triggers, сохранив базу. Удалять namespace для остановки нельзя: это потеря данных. Восстановление после потери namespace пока не проверено.
