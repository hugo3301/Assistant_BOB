# BOB: диалоговое ядро

Дата: 4 ноября 2026 года. Beads: `bob-wrh.3`. Реализован локальный прототип на Node.js 24+ и встроенной SQLite, без npm-зависимостей. GLM-4.7-Flash вызывается через существующий разрешённый Workers AI API. Telegram и постоянное облачное размещение пока не подключены.

## Возможности

Сохраняются задачи с внешним сроком, события с точным началом и интервалы работы, связанные с задачей. Рабочий интервал не меняет срок сдачи. Поддерживаются создание, перенос, завершение задач и отмена дел. Завершение/отмена родительской задачи отменяет её открытые рабочие интервалы.

SQLite хранит профиль владельца, записи, фокус разговора, последние пять ходов, ожидаемое уточнение, результаты обработанных сообщений, очередь напоминаний и локальный расход ИИ. Это собственная база BOB; Beads остаётся трекером разработки.

Фразы «перенеси её сдачу» и «её я сдал» используют сохранённый фокус. При неоднозначности приложение показывает список своих записей. Выбор номера не требует нового запроса к модели. Уточнение недостающего времени также выполняется без модели и переживает перезапуск. Уточнение действует до 24 часов; относительная дата привязана к исходному сообщению, включая переход через полночь. `/cancel` очищает уточнение; новый явно начатый запрос заменяет его.

Быстрые команды не используют ИИ:

| Команда | Результат |
|---|---|
| `/today` | Дела сегодня и просроченные |
| `/week` | Следующие семь календарных дней, включая сегодня, и просроченные |
| `/ahead` | Все известные открытые обязательства, включая далёкие сроки и дела без даты |
| `/tasks` | Все открытые задачи, события и интервалы работы |
| `/find текст` | Поиск открытых записей по подстроке названия/id во всей базе своего владельца |
| `/cancel` | Отмена ожидаемого уточнения |

Первые четыре названия команд — реализация предложения, ещё не утверждённый пользователем интерфейс. `/projects`, полноценные проекты, регулярные серии и iCalendar в этом ядре не реализованы.

## Как проходит сообщение

1. Адаптер передаёт доверенный id владельца и стабильный id входящего сообщения. Доступ ограничен явным списком владельцев; будущий Telegram-адаптер должен получать id из проверенного update, не из текста и не из модели.
2. Команда/сохранённое уточнение обрабатывается напрямую. Для свободного текста GLM предлагает предметные функции. Контекст ограничен 30 открытыми записями и тремя сокращёнными предыдущими ходами. Для поиска за пределами этого контекста существует `/find`.
3. Программа проверяет схему, владельца, цель, полномочия на смену срока, исходную фразу даты, календарь и конфликты интервалов. Идентификатор от модели сам по себе не разрешает изменение. Срок сдачи меняется только при явном запросе со словами «срок/сдача/дедлайн» и глаголом изменения; запрет «срок не меняй» имеет приоритет. Отрицание выполнения блокирует закрытие.
4. Весь пакет проверяется до записи. Одна корректирующая попытка допустима при ошибке схемы/пропущенном явном сроке. Даты/неоднозначность требуют уточнения. Пакеты с вопросом или просмотром и изменениями не смешиваются.
5. Записи, напоминания, история и фактическое подтверждение фиксируются одной транзакцией. Ответ пользователю строит код по сохранённому действию. Модель не генерирует самостоятельное «готово».

Один простой ход делает не более двух API-вызовов; обычный успешный ход — один. Повтор того же id/текста возвращает сохранённый результат без повторного действия и без ИИ. Другой текст с тем же id отклоняется. Незавершённую обработку можно перехватить после трёхминутной аренды; старый процесс теряет право записи. Проверка версии профиля предотвращает запись по устаревшему контексту между экземплярами приложения. Адаптеры должны изменять пользовательские данные через транзакционный путь ядра, а не прямым SQL.

Это ограниченные правила для поддерживаемого ввода, а не доказательство понимания любого русского сообщения. Для неоднозначных составных просьб интерфейсу полезен предварительный показ изменений; такой универсальный режим пока не реализован.

## Даты и часовые пояса

Модель копирует `due_text`/`when_text` из сообщения. Код разрешает «сегодня», «завтра», «послезавтра», явные `12 ноября [2026]`, `12.11[.2026]`, `2026-11-12`, день недели и время `в 15:00`/`в 15`. День недели без определения означает ближайший такой день, включая сегодня. Часовой пояс берётся из профиля; «по Москве»/«мск» поддержан явно. В подтверждении всегда видна вычисленная дата. Отсутствующее время срока хранится как дата без времени, без выдуманной полуночи и без отдельного почасового уведомления.

Технические начальные значения прототипа: `Asia/Tomsk`, напоминание за 60 минут. Пользователь ещё не подтвердил эти настройки. Утреннее время по умолчанию отсутствует, поэтому утренняя отправка выключена. Настройки задаются через `Store.settings`; пользовательская форма ещё не подключена.

Границы месяца/года, несуществующие даты и противоречие даты/дня недели проверяются. Прошедшая дата без года требует года. Неизвестные модификаторы, «следующую пятницу», «после пар», повторения, недостающее время события и неоднозначные часы при переводе времени требуют уточнения. Календарный парсер намеренно ограничен; общий импорт RRULE/EXDATE и изменение серий — отдельная работа. Полная проверка соответствия нескольких дат нескольким действиям в произвольном предложении не заявляется.

Для рабочего интервала длительность извлекается кодом из «на час», «на полчаса», «на 45 минут» и аналогичных числовых форм. Проверяются наложения известных интервалов и выход за точный срок сдачи. Если у занятия неизвестна длительность, планирование работы в потенциально занятом промежутке останавливается для уточнения. Встреча без длительности хранит её как неизвестную; она не становится известным свободным окном.

## Напоминания независимо от ИИ

`ReminderWorker.tick(send)` выбирает наступившие сохранённые напоминания и вызывает переданный транспорт. При переносе/отмене старые записи очереди отменяются, при новом времени создаётся новая. Собственный интервал напоминания сохраняется при переносе. «Без напоминания» отключает его. Добавление времени к задаче с датой без времени создаёт соответствующее напоминание.

Напоминания имеют аренду на две минуты, повтор после ошибки (5 секунд, далее удвоение до 5 минут), максимум пять неудачных отправок и постоянный ключ дедупликации. Истёкшее событие пропускается; пропущенное напоминание отправляется, пока само событие ещё впереди. Утренняя сводка ставится один раз на локальную дату, максимум в течение восьми часов после настроенного времени; перед повторной отправкой содержание обновляется из базы.

После аварии между внешней доставкой и записью `sent` возможен дубль. Уже начавшуюся внешнюю отправку нельзя атомарно отозвать переносом события. Гарантия exactly-once не заявляется. Будущий транспорт должен ограничивать время запроса относительно аренды и корректно обрабатывать ошибки/длины сообщений.

Сейчас проверен локальный тестовый транспорт. Фоновая служба не установлена; `chat` сам по себе не запускает отправку, постоянная доставка не работает. Нужен Telegram-адаптер и регулярно вызываемый worker. Node SQLite не является готовой D1-интеграцией: для Cloudflare нужны адаптация хранения/транзакций и повторные проверки. Наличие локальной очереди ещё не означает готовность круглосуточного бота.

## ИИ, данные и бюджет

Фиксирована бесплатная проверенная модель `@cf/zai-org/glm-4.7-flash`: temperature 0.1, max_tokens 1200, stream false, thinking отключён. Таймаут 45 секунд. Платного переключения нет. Перед запросом резервируется консервативная оценка расхода; после ответа учитывается `usage.neurons`. Неизвестный исход расходует резерв целиком. Резерв переживает сбой процесса. Начальный локальный дневной предел 7500 neurons; проверочный прогон использует 300.

Счётчик действует в пределах конкретной базы BOB, день — UTC. Он не видит эксперименты и другие приложения аккаунта и не заменяет лимит Cloudflare/платёжный кабинет. Перед общим размещением нужно объединить бюджет или учесть остальные потребители. После ошибки/лимита доступен просмотр и независимый worker, но сохранение нового свободного текста требует доступного ИИ.

Запросы к Workers AI содержат текущее сообщение, ограниченную историю и данные открытых дел. Это внешний API. Токен находится только в исключённом `.env`, локальные пользовательские базы и журналы — в исключённом `/work/`. Исходящие заголовки/сырой токен не логируются; транспортные ошибки сохраняются общим кодом. База содержит личные данные в открытом виде на диске; шифрование и проверенное резервное восстановление ещё не реализованы. Удалённого Git/backup пока нет.

## Запуск и проверка

Из `D:\Assistant_BOB` с Node.js 24+:

```powershell
npm.cmd test
npm.cmd run demo
npm.cmd run chat
```

`demo` не вызывает API, использует синтетическую модель и локальную тестовую доставку. `chat` читает существующий `.env`, сохраняет состояние в `work/bob.sqlite` и вызывает настоящий API для свободного текста. `/exit` закрывает консоль. Без env работают обзорные команды. Установка npm-пакетов не нужна.

Настоящая интеграционная проверка (расходует бесплатную квоту):

```powershell
node --env-file=.env scripts/live-core-check.mjs
```

Прогон 2026-11-04T03:22:07.561Z: пять реальных вызовов GLM, 58.0436 neurons по API; ни одной корректирующей попытки. Создание задачи к 12 ноября → закрытие базы и повторное открытие → перенос срока на 14 ноября → завершение. Затем встреча завтра в 15:00 → перенос на 16:00. `/week` обошёлся без ИИ. Локальный worker доставил одно уведомление по новому времени; повторный tick ничего не отправил. Все шесть проверяемых итогов выполнены. Синтетические данные/состояние: `work/core-validation/2026-11-04T03-22-07-561Z/result.json` и соседняя SQLite.

Локальная проверка: 31 тест ядра и 27 сохранённых тестов API-эксперимента. Покрыты реальные перезапуски, уточнения через полночь, идемпотентность, чужой владелец, ошибочный пакет, запрет изменения внешнего срока, отрицание выполнения, конфликты, устаревший контекст, восстановление аренды, отмена/повторы доставки и независимость от ИИ. Это регрессии поддержанного поднабора; общая точность на личных обязанностях пока не измерена.

## Следующий этап

Продолжение ведётся в Beads: Telegram-адаптер и выбор постоянного размещения. Нужны токен своего бота из BotFather (передавать через локальный секрет, не обычным сообщением/коммитом), подтверждённый Telegram owner id, часовой пояс и время утренней сводки. Существующий Workers AI токен не предоставляет права на Workers/D1/deploy. Для проверки расписания нужен реальный iCalendar и правила отбора своих занятий; их пока нет. Продакшн-развёртывание, подключение Telegram и действия от имени пользователя не выполнены.
