# BOB: аудит гипотез

Дата: 2026-11-04. Задача: `bob-wrh.1`. Основание: весь текущий набор требований в `requirements.md`, вариантов в `implementation-options.md` и переписка с пользователем.

«Подтверждено пользователем» означает потребность/вводные. Это не подтверждение качества ещё не реализованного бота. «Подтверждено платформой» означает документацию или наблюдение интерфейса, а не проверенную интеграцию BOB.

| ID | Гипотеза / исходное предположение | Состояние и вывод |
|---|---|---|
| H01 | Telegram удобен как основное окно | Выбран пользователем. Удобство реального диалога ещё проверяется; команды дополнить кнопками и обычным текстом. |
| H02 | Каждое утро полезна сводка | Потребность подтверждена. Время, тихие часы, размер и порядок дел не определены. |
| H03 | Напоминание за час подходит всем событиям | Заблаговременное сообщение подтверждено; час — пример. Для дороги и подготовки нужны разные интервалы. |
| H04 | Недельного списка достаточно для общей картины | Недельный просмотр и дальний обзор запрошены. Показать конечный срок, начало подготовки, зависшие дела и обязательства без даты. |
| H05 | Можно автоматически выбрать свои пары из iCal | Проверяемо только на реальном файле. Нужны признаки групп/подгрупп, пользовательский выбор и сохранённые правила. Файл ещё не получен. |
| H06 | Однократный импорт расписания всегда актуален | Не подтверждено. Для файла нужен свежий импорт; для ссылки — проверка доступности и обновлений. Переносы, отмены, повторы и отсутствие дублей проверяются отдельно. |
| H07 | Одного ввода семестровых сдач достаточно навсегда | Пользователь готов к начальному вводу. Изменения сроков и новые задания всё равно нужно сообщать или получать из выбранного источника. |
| H08 | Большую сдачу достаточно напомнить перед дедлайном | Непригодно для подготовки. Нужны трудоёмкость, промежуточные результаты и согласованный момент начала. |
| H09 | Проект можно представить одной задачей | Для обзора нужен ближайший результат, следующие действия, сроки и ожидания. Состав проектов и существующие трекеры ещё не известны. Полную синхронизацию не обещать. |
| H10 | Три тренировки в неделю означают фиксированные дни | Подтверждена только частота. Фиксированный или гибкий график, длительность и дорога не заданы. |
| H11 | По фиксированному рациону понятны нужные функции | Пока неизвестно. Уточнить, нужны ли покупки, готовка, контейнеры, приёмы пищи или просто учёт времени. Не навязывать учёт калорий. |
| H12 | Любое свободное окно можно заполнить работой | Не подтверждено. Учитывать дорогу, сон, отдых, резерв и оценки длительности; показывать перегруз и не переносить внешний дедлайн ради красивого плана. |
| H13 | Достаточно набора команд без диалога | Пересмотрено: пользователь явно обозначил ИИ как важную часть универсальности и удобства. Проверять свободный ввод, уточнения, исправления и контекстные просьбы уже в первом прототипе. |
| H14 | Модель сама надёжно помнит все обязательства | Не принимать. Факты, сроки, связи и пользовательские исправления хранить в базе; передавать модели подходящую выборку. |
| H15 | ИИ можно доверить все записи в базу | Не принимать. Вызовы разрешённых функций проходят проверку полей, дат, объектов и полномочий; успех сообщается только после реальной записи. |
| H16 | Инструкция «выдай JSON» гарантирует корректные действия | Опровергнута как практическая гарантия в пробах playground. Нужны строгая проверка формата и отдельная проверка смысла. Ошибку нельзя исполнять или молча чинить угадыванием. |
| H17 | Все модели в каталоге бесплатны | Неверно. В аккаунте видны сторонние и платные модели. Проверять конкретный идентификатор, хостинг и требование оплаты. |
| H18 | Бесплатный круглосуточный облачный путь возможен | У аккаунта через UI подтверждён Current plan: Free. Документация даёт квоты Workers/D1/Queues/AI. API-вызов от имени аккаунта, webhook, доставка и нагрузка BOB пока не проверены. |
| H19 | Лимит 10 мс не позволит ждать ответа модели | Уточнение: это CPU, а не время ожидания сети. Активные вычисления всё равно ограничены. Для медленного ИИ нужен устойчивый асинхронный путь, не один короткий фоновый вызов после webhook. |
| H20 | Бесплатного ИИ хватит при любом использовании | Неверно. Дневная квота зависит от токенов, модели, повторов и длины цепочки. Есть расчётные сценарии в ai-design.md; реальный расход ещё не измерен. |
| H21 | Голос и скриншоты автоматически доступны вместе с текстом | Нет. Это отдельные модели/эндпойнты, квоты, форматы и проверки. Голос — перспективный следующий способ ввода; работу изображений через выбранный API ещё проверить. |
| H22 | Импортированный текст может задавать действия агенту | Не принимать. Содержимое календаря и пересланных материалов — данные. Пробы показали смешение уровней инструкций; функции кода должны ограничивать последствия независимо от модели. |
| H23 | Нужно сразу строить большую сеть агентов и векторную память | Оснований пока нет. Начать с одного диалога, контролируемых функций и структурированных запросов; усложнять по найденным ограничениям. |
| H24 | Помощник гарантирует отсутствие любых сюрпризов | Нельзя обещать для неизвестных обязательств или устаревших источников. Показывать свежесть расписания, неполные данные и дела, которые пора пересмотреть. |
| H25 | Бесплатный тариф равен гарантированной бесперебойности | Нет. Нужны сохранение состояния, повторы, контроль пропусков и резервная копия; регистрация сама по себе этого не обеспечивает. |

Предлагаемая первая проверка продукта: естественным сообщением добавить дело, контекстно исправить его, увидеть запись в обзоре и получить сохранённое напоминание. Импорт своего расписания — следующий сценарий на реальном файле. ИИ участвует с первой проверки; календарь и доставка сохраняют самостоятельную работоспособность.

Технические источники, расчёты и протокол проб: `ai-design.md`, `ai-evaluation.md`.
