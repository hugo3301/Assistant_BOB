# Изменения в BOB

Нужны Node.js24+ и npm. Установи зависимости через `npm ci`; перед PR выполни `npm run ci`. Автоматические проверки не должны использовать настоящие Telegram/AI/Calendar API или личные дела.

Для разработки используй свою ветку и вымышленные fixtures. Пиши тесты на важное поведение: неоднозначные даты, изоляцию участников, повторы, отказ провайдеров, расход квоты. Модельное предложение не должно обходить проверку приложения.

Не коммить `.env`, ключи, сырой пользовательский диалог, голосовые, базы, логи и временные результаты. Примеры конфигурации держи пустыми. Внешние ключи хранятся только в закрытом хранилище соответствующего сервиса.

В PR опиши проблему, итоговое поведение и проверку. Не запускай живые скрипты из `scripts/check-*-live.mjs` без отдельного ограниченного согласия. Не меняй TLS-доверие ОС, бесплатные тарифы и сохранённые настройки пользователей ради теста.

Beads — основной трекер команды; содержательные решения хранятся в `docs/`. GitHub Issues подходят для внешних bug reports и предложений, которые сопровождающий переносит в Beads при выборе работы.
